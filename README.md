# Fail2Bug

从飞书电子表格或本地 Excel 的执行结果筛选失败用例，生成可编辑草稿，人工确认后批量写入飞书多维表格。

当前实现：一条 fail 对应一条草稿；飞书导入后返回审核链接，在网页统一填写版本、设备、环境，逐条补充分类、四段描述和附件，确认后写入。按条推断问题类型、子模块和发生概率，依据不足时提示补充。提交人使用发起人的 open_id。已提交缺陷更新原单。

## 本地启动

需要 Python 3.11 或更新版本。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,bot]"
cp .env.example .env
f2b serve
```

打开 <http://127.0.0.1:8000>，点击“体验示例”。示例中有一条缺少实际结果，补齐后即可模拟提交。所有示例提交只保存在本地，演示批次即使在 live 模式下打开也不会写入飞书。

如果运行环境已经安装依赖，也可以从项目目录运行：

```bash
PYTHONPATH=src python3 -m fail2bug serve
```

## 接入飞书

1. 在飞书开放平台创建企业自建应用。启用应用机器人。
2. 开通电子表格读取、多维表格读写权限；使用机器人时，再开通接收单聊消息、接收群聊中 @机器人的消息、以应用身份发送消息的权限。
3. 把应用添加为执行表和缺陷表的协作者，分别给予阅读和编辑权限。应用权限与文档协作者权限都需要配置。
4. 按下面的字段规格检查缺陷表。在 `.env` 中填写 `APP_ID`、目标 `APP_TOKEN` 和 `TABLE_ID`（变量均带 `F2B_` 前缀）；应用密钥和团队口令使用下述钥匙串引用。
5. 将 `F2B_MODE` 改为 `live`，重启服务。打开页面输入访问口令后粘贴真实执行表链接。

密钥不要贴进聊天或提交仓库。macOS 可用钥匙串保存应用密钥和团队访问口令，在 `.env` 中只填写 `F2B_APP_SECRET_KEYCHAIN`、`F2B_ACCESS_KEY_KEYCHAIN` 引用（对应钥匙串 service 分别为 `file2bug.app-secret`、`file2bug.access-key`，account 为引用值）。已有 `.env` 明文配置兼容读取；管理页新增或更换的应用密钥始终保存在钥匙串。

### 执行表

首版支持 `https://团队.feishu.cn/sheets/表格token?sheet=工作表ID` 链接。

必需列：`用例ID`、`PRD模块`、`标题`、`优先级`、`操作步骤`、`预期结果`、`执行结果`。

也支持分别用`用例编号`、`所属模块`、`用例标题`、`测试步骤`作为上述对应列的表头。

可选列：`前置条件`、`测试数据`、`实际结果`、`备注`、`证据`、`需求点`、`发生概率`（或 `复现概率`）、`复现次数`、`执行次数`。表头在前 10 行内探测，按列名读取，支持调整列顺序。

- `fail/failed/f/ng/nok/失败/不通过/未通过/失败（Fail）` 生成草稿。
- pass、blocked、skip 和未执行均不生成草稿。
- 不认识的执行结果单独展示，避免被当成通过。
- 优先读取`实际结果`，该列缺失或对应单元格为空时读取同一行的`备注`，两处都没有内容时才要求补充。
- 优先级使用 `P0/P1/P2/P3`；不支持的值要求人工修改。
- 源表的用例ID不可为空。缺失时应先修正源表再重新导入。
- 多行步骤完整保留；没有实现合并单元格自动补齐，请确保每条用例对应完整独立的一行。
- 缺陷标题使用用例标题，不额外拼接模块名。标题开头与模块相同的方括号前缀会被去除，模块仍单独记录。
- 一次读取完整工作表网格，默认上限 10000 行 / 100 列，超限明确拒绝，不静默截断。
- 在线来源使用 sheets 链接，不接受 wiki 包装链接。本地来源支持 `.xlsx` 和包含执行表的 `.zip`，见下文。

### 缺陷表

`.env.example` 提供字段映射，每次实际提交前检查字段名及类型。

| 逻辑字段 | 默认字段名 | 类型 |
| --- | --- | --- |
| 标题 | 缺陷标题 | 文本 |
| 复现步骤 | 复现步骤 | 文本 |
| 预期 | 预期结果 | 文本 |
| 实际 | 实际结果 | 文本 |
| 优先级 | 优先级 | 文本或单选（P0/P1/P2/P3） |
| 提交人 | 提交人 | 文本或人员（填写 open_id） |
| 版本 | 版本 | 文本 |
| 设备 | 测试设备 | 文本或多选（使用已有选项） |
| 环境 | 环境 | 文本或多选（使用已有选项） |
| 用例ID | 关联用例 | 文本 |
| 证据（可选） | 由 `F2B_FIELD_EVIDENCE` 指定 | 文本 |
| 状态（可选） | 由 `F2B_FIELD_STATUS` 指定 | 文本或单选 |
| 所属项目（可选） | 由 `F2B_FIELD_PROJECT` 指定 | 文本或单选 |
| 来源链接（可选） | 由 `F2B_FIELD_SOURCE` 指定 | 文本 |
| 问题类型 | 由 `F2B_FIELD_PROBLEM_TYPE` 指定 | 文本或多选 |
| 模块 | 由 `F2B_FIELD_MODULE` 指定 | 文本或多选 |
| 子模块 | 由 `F2B_FIELD_SUBMODULE` 指定 | 文本或单选 |
| 发生概率 | 由 `F2B_FIELD_FREQUENCY` 指定 | 文本或单选 |
| 截图或视频 | 由 `F2B_FIELD_ATTACHMENTS` 指定 | 附件 |

证据原文可通过 `F2B_FIELD_EVIDENCE` 映射到独立文本字段；真实文件通过 `F2B_FIELD_ATTACHMENTS` 映射到现有附件字段。备注首行为写入日期与 `QA:`，随后只合并版本、用例和来源，不写入证据原文。默认不修改远程表结构，新增字段前需先获得使用人的同意。

问题类型、子模块、发生概率没有批次默认值，均按条推断，并展示依据：

- 问题类型：从实际结果的明确症状匹配已有选项；实际结果只写“已提单”或内容不足时留空，不从预期结果中的反例推断。
- 发生概率：使用明确的复现次数、复现率或“必现 / 高概率 / 偶现 / 低概率”等记录。数值按 ≥80%、≥50%、≥10%、<10% 分为四档。无法推断时逐条填入 `Very High / Frequent`，可以在审核时修改。
- 模块：沿用源表名称。缺陷表没有对应的多选选项时，确认写入后由飞书添加该选项。
- 所属项目：可在批次信息中直接输入名称。如果缺陷表用单选且没有该名称，确认写入后由飞书添加选项。
- 子模块：优先使用与需求点一致或标题明确命中的已有选项；无法确定时使用模块名。此回退可能在子模块单选字段中产生同名选项，不创建新字段。
- 人工修改后保留人工值。配置了相应字段映射时，确认写入前要求分类完整；可先忽略尚未补齐的条目。

设备、系统和其他多选字段使用可搜索的勾选面板：选中后保持展开，可继续选择；重新展开仍显示全部选项。单选字段使用固定选项列表。

### 本地执行文件和附件

在网页选择 `.xlsx` / `.zip`，或直接在机器人单聊发送文件。CLI 也可使用：

```bash
f2b import --file '/绝对路径/执行结果.zip' --sheet '执行结果'
```

工作表名称可省略，默认读取第一个工作表。Excel 使用上述列名，标准绘图图片按锚点所在用例行关联，`证据`列中通过 WPS 插入到单元格的图片也会关联到该行。外部截图、视频和日志需与 Excel 一起打包，`证据` 列填写相对路径或唯一文件名，例如：

```text
执行结果.zip
  执行结果.xlsx        # 某条 fail 的证据列：evidence/截图.png；evidence/录屏.mp4
  evidence/截图.png
  evidence/录屏.mp4
```

ZIP 中需要恰好一个 Excel；支持 `证据` 单元格中的文件超链接。找不到文件或文件名重名时显示告警，等待补充，不把文件名当成文件本体。直接通过网页或聊天发送独立 Excel 时，电脑上的外部文件不会随之传输，应使用 ZIP。本机 CLI 可读取 Excel 所在目录内的证据文件。仅有远程链接时保留原文，不自动下载。

可使用仓库中的 [本地导入示例](examples/Fail2Bug_本地导入示例.zip)；包含一条明确标记的测试用例、内嵌图片、外部截图和日志。

### 补充附件

在某条缺陷的“检查 / 修改”或“补充字段”中选择文件。文件先保存在本机草稿中，可预览；点击页面底部确认写入后才上传飞书并绑定到附件字段。

- 飞书在线表格内的图片、视频等实际附件按失败用例所在行下载并关联，浮动图片按左上角所在行关联。重复素材在同一用例内去重。应用需要执行表的阅读与素材下载权限。
- 仅有文件名或分享链接时保留原文，可在网页补充实际文件，也可在聊天发送“附件 3”后发送证据。下载失败或超限会显示导入提示。
- 每条缺陷最多 10 个文件，单文件默认上限 200MB（`F2B_MAX_ATTACHMENT_MB`）。20MB 内直传，更大的文件使用分片。
- 支持图片、视频、PDF、TXT 和日志，拒绝 SVG；文件名和原始证据文本分别保留。本地导入文件和展开后的 ZIP 默认不超过 200MB（`F2B_MAX_IMPORT_MB`）。
- 上传失败会保留可重试状态，不会把没有成功绑定的文件显示为已完成。
- 原单补充会保留原来已有的附件；已写入的附件在飞书中管理。

复现步骤固定使用以下四段。测试数据放在前提段，空内容保持空白：

```text
【前提】：

【操作】：

【预期结果】：

【实际结果】：
```

如果现有缺陷库只有一个描述字段，可把 `F2B_FIELD_STEPS`、`F2B_FIELD_EXPECTED`、`F2B_FIELD_ACTUAL` 配为同一个字段名，仍按上述四段写入。版本、用例ID和来源链接可共同映射到备注字段，首行填写上海时区实际写入日期与 `QA:`（姓名留空），后面只保留下面三段；兼容旧配置中证据原文也映射到备注的情况，但不输出证据原文。结果待确认的提交重试仍使用原始日期与内容。

```text
2026-11-05 QA:
【测试版本】
0.1.1
【关联用例】
TC_0643
【来源链接】
https://your-team.feishu.cn/sheets/…?sheet=…
```

人员字段使用 `[{"id":"ou_..."}]` 写入，不能直接填姓名。设备、系统的多选字段使用数组，工具会检查选项已存在，避免产生错误选项；审核页提供已有选项提示。主列若为公式，应将标题映射到它引用的可编辑文本字段。

若缺陷表还有必填字段（如严重级别），应先在目标表配置可接受的默认值，或在接入时扩展映射。未配置的必填字段会导致实际提交失败。

### 机器人入口

先启动网页服务，再开另一个终端运行：

```bash
source .venv/bin/activate
f2b bot
```

在飞书开发者后台将事件接收方式设置为长连接，订阅 `im.message.receive_v1` 并发布应用。把允许触发的用户 open_id 写入 `F2B_ALLOWED_USERS`（逗号分隔）。

不知道自己的 open_id 时，可私聊发送“我的ID”，也可在群里 @机器人 发送“我的ID”（支持文本和富文本消息）。它会回复消息发送人本人的 ID，同时记录在本机 `data/last-identity.json`。群聊必须实际 @本机器人；不回复未 @或仅 @其他人的消息。该查询无需预先进入允许用户列表，也不会因此获得解析权限。可在本机管理页添加允许用户，保存后机器人会在当前任务结束后自动重连。

单聊机器人，或在群聊 @机器人：

```text
解析 https://你的团队.feishu.cn/sheets/表格token?sheet=工作表ID
```

机器人返回带“打开审核与补充页面”链接的卡片。点击后可直接打开当前批次，无需另外输入团队访问口令；网页为主要审核入口，手机上以卡片展示条目，点击“详细补充”填写完整表单。常用命令：

| 命令 | 用途 |
| --- | --- |
| `帮助` | 查看命令说明 |
| `使用 <批次前8位>` | 恢复本人已保存的批次 |
| `审核链接` / `查看` | 重新获取当前批次的网页审核链接 |
| `详情 3` | 查看第 3 条的推断依据和完整四段描述 |
| `附件 3` | 将下一张图片、视频或文件关联到第 3 条 |
| `取消附件`、`告警` | 取消待收附件、查看导入告警 |

消息卡片用于展示和跳转，不需要配置卡片回调。机器人收到当前操作者的 open_id 并预填提交人，仅允许恢复本人批次；会话和批次均保存在 SQLite，重启后可继续。发送新文件只导入草稿，在网页确认后才写入。旧的文字修改、选择和确认命令继续兼容。

审核链接有效期 24 小时，仅可查看、编辑和确认写入对应批次；不会因此获得其他批次或整个工作台权限。链接含本批次的访问凭证，使用 URL fragment 传递，验证后从地址栏清除；团队口令不出现在链接中。可将链接发给参与此批次审核的同事。过期后由发起人在机器人发送“审核链接”重新获取。

目标为人员字段时保留 open_id；目标为文本字段时才可以填写姓名。通过机器人创建的批次始终优先使用消息发送人的 ID。直接从网页导入时，使用配置的 `F2B_DEFAULT_REPORTER` 预填，审核时需要确认；网页直开目前没有接入飞书用户登录，不能自动识别当前用户。

配置 `F2B_DEFAULT_REPORTER_NAME` 后，审核页会显示已绑定用户的姓名，后台仍使用 ID 写入人员字段。这个姓名仅用于展示，不用于按姓名匹配其他用户。

`F2B_BASE_URL` 必须是审核人能访问的服务地址。机器人长连接不需要公网事件回调地址。

### 本机管理页

在服务电脑打开 <http://127.0.0.1:8000/admin>，输入工作台访问口令。页面沿用白色 / 深色主题，可配置目标缺陷表、字段映射、机器人启停、App ID / App Secret、允许用户、网页导入默认值和导入上限。

- 管理页及其 API 同时限制连接来源和 Host 为本机，拒绝代理头；局域网审核不受影响。审核链接不能进入管理页。
- 已保存的密钥不返回 HTML / JSON，页面只显示「•••••••• 已配置」。留空保留原值，新密钥通过标准输入写入 macOS 钥匙串，不进入命令行参数、日志或数据库。浏览器所有者仍能检查自己新输入的内容，星号无法阻止这一点。
- 「检查连接」和「验证并保存」只做应用鉴权、读取表字段和机器人信息，不创建缺陷或修改表结构。验证失败或版本冲突不会覆盖原配置。
- 非密钥设置存入本机 SQLite，优先于 `.env` 的同名设置。网页后续请求立即使用新快照，在途请求继续使用原配置；机器人等队列处理完成后原地重启并重连，需保持 `f2b bot` 进程运行。
- 切换目标表只影响新导入的批次。旧批次仍绑定原目标，切回原表后才能继续提交；历史缺陷不会被自动搬迁。
- 群聊 @机器人时，提交人为实际发起解析的同事，不是群主或默认提交人。同事需在允许用户列表内，且应用已发布并对他可见；网页直接导入仍使用配置的默认提交人，尚未接入飞书网页登录。

### 同一局域网使用

在服务电脑的 `.env` 设置以下配置，IP 替换为这台电脑当前的局域网地址：

```dotenv
F2B_HOST=0.0.0.0
F2B_BASE_URL=http://192.0.2.10:8000
```

重启 `f2b serve` 和 `f2b bot`。同事的电脑、手机连接同一局域网后，在飞书点击审核链接即可打开。无需公网域名或隧道。服务电脑须保持运行；IP 变化后更新 `F2B_BASE_URL` 并重启机器人，再获取新链接。若其他设备连接超时，检查是否同网段、路由器是否启用客户端隔离，以及服务电脑是否允许 8000 端口的入站连接。

## 技术结构

Python + FastAPI 提供接口和页面，Jinja2 + 原生 JavaScript 实现审核界面，SQLite 存储批次，HTTPX 访问飞书 API，官方 `lark-oapi` SDK 接收机器人事件。无需前端构建或独立数据库服务。

```text
src/fail2bug/
  app.py       页面、审核和提交接口
  access.py    批次审核链接签名、有效期和范围校验
  parser.py    读取表格内容、筛选 fail、模板组装
  inference.py 按条推断分类和频率，记录依据
  repro.py     四段复现描述
  local_source.py 本地 Excel、ZIP 和证据关联
  service.py   审核保存与提单逻辑
  feishu.py    应用鉴权、电子表格读取、多维表格写入
  store.py     SQLite 草稿和提交状态
  bot.py       长连接机器人
  chat.py      聊天审核命令、会话和卡片展示
  templates/   页面模板
  static/      样式和浏览器交互
```

运行一个网页服务进程（默认 `f2b serve`），机器人可以单独运行。数据库包含执行结果和缺陷描述，应按团队数据要求保存与备份。

## 提交行为

- 点击确认前先保存全部修改，校验选中条目和批次信息，缺失时整次不提交。
- 界面一次确认多条，后台逐条调用新增记录接口，便于返回每条结果，单条失败不会影响其余条目。
- 已成功的条目不再重复提交；同一批次并发点击会被拒绝。
- 每个请求在发出前保存 UUID 和请求内容，作为飞书接口 `client_token`。网络结果不明确或进程中断后，重试沿用同一请求内容和编号；该条目暂时锁定内容编辑。
- 草稿绑定创建时的缺陷库，切换目标库后不能将旧批次误提交到新库。
- 已有 `record_id` 的缺陷可补充问题类型、模块、子模块、发生概率、四段复现描述和附件，使用更新接口；不会因为补充字段再建一条。该操作保留原标题、优先级和状态。旧记录的新格式和推断结果也需确认后才写入。
- 本地批次防重不等于历史缺陷去重。重新导入同一份执行表会产生新批次，请由审核人检查是否已提过；不修改历史缺陷状态。
- 自动测试使用模拟 HTTP 响应；真实联调使用单独标记的测试记录。已验证新增、人员与多选字段、操作编号防重、原单补充分类与附件、四段复现描述、子模块同名回退和聊天卡片收取。本地示例 ZIP 的内嵌图片、外部截图和日志已通过网页接口导入，并绑定到同一条联调原单；聊天文件下载仍需实际发送文件验证。
