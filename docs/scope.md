# 首版范围与选型

目标：把执行表中的 fail 用例整理成缺陷草稿，测试同学检查后一次提交，减少复制粘贴。

## 用户流程

1. 在网页或机器人导入飞书执行表链接、本地 Excel 或包含执行表及证据的 ZIP。
2. 读取执行表，一条 fail 生成一条草稿，其他结果分开计数，未识别结果单独展示。
3. 机器人回复当前批次的审核链接，在网页填写版本、设备、环境。提交人使用操作者 open_id；逐条推断子模块、问题类型和发生概率。未知类型与概率留空，未知子模块回退为模块名。点击“详细补充”检查四段复现描述和附件，手机适配为条目卡片。
4. 勾选要提交的条目。缺少实际表现等信息时提示补充，不自动猜测。
5. 确认后写入多维表格，逐条显示成功链接或失败原因，失败项可重试。

## 选型

| 部分 | 选择 | 原因 |
| --- | --- | --- |
| 服务端 | Python 3.11+ / FastAPI | 与表格处理和飞书 Python SDK 配合，一套服务提供界面及接口 |
| 审核界面 | Jinja2 / HTML / CSS / 原生 JavaScript | 页面需求简单，无需前端构建链 |
| 飞书读写 | HTTPX / tenant_access_token | 固定字段映射，应用身份写入，提交人独立记录 |
| 机器人 | 官方 lark-oapi SDK 长连接 + 消息卡片 | 接收导入并返回网页链接，详细审核在网页完成 |
| 存储 | SQLite | 保存批次、草稿、提交状态，单机即可运行 |

## 首版边界

支持飞书电子表格、Excel、ZIP 来源和一个配置好的多维表格目标。逐条形成草稿，人工检查重复；不做根因归类、相似度匹配、跨轮次去重或 reopen。证据原文与实际附件分别保存；内嵌图片按行关联，外部附件按证据路径或唯一文件名关联。已提单支持补充四项分类、四段复现描述和附件，更新原单。分类使用明确规则及已有选项；发生概率必须有实际频率依据，单条 fail 不作为复现率。LLM 和 OAuth 用户身份不进入本版。业务字段复用现有表结构，新增字段需使用人确认；子模块同名回退可产生新选项。

服务运行在局域网电脑，通过局域网 IP 提供审核页。同事和手机需在同一局域网；服务电脑须保持运行。审核链接限时 24 小时，只授权当前批次，点击自动验证后打开，不开放其他批次和工作台。

## 验收

使用真实验证表跑通“导入 → 修改 → 勾选 → 提交 → 返回链接”。每条选中 fail 的标题、步骤、预期、实际、优先级及批次信息与审核内容一致；未勾选条目不写入；同批次重复点击不重复提单；单条失败可单独重试。演示模式用于先验证操作流程，真实读写需配置应用后联调。
